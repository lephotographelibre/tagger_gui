## User

comment forcer les requetes HTTP a utiliser ipv4

## Assistant

La cause probable du ralentissement est que Python essaie IPv6 en premier, ça timeout, puis bascule sur IPv4.

**Solution : monkey-patch de `socket.getaddrinfo`** ajouté dans `tagger.py` juste après `import requests` :

```python
import socket
import requests
# Forcer IPv4 (evite les lenteurs dues aux tentatives IPv6 qui echouent)
_orig_getaddrinfo = socket.getaddrinfo
def _getaddrinfo_ipv4_only(host, port, family=0, type=0, proto=0, flags=0):
    return _orig_getaddrinfo(host, port, socket.AF_INET, type, proto, flags)
socket.getaddrinfo = _getaddrinfo_ipv4_only
```

Discogs répond bien aux deux protocoles, mais la **connexion IPv6 est cassée** (routage ou FAI ne l'achemine pas).

**Chaîne complète DNS → connexion :**
```
requests.get("api.discogs.com")
    ↓
socket.getaddrinfo("api.discogs.com")   ← résolution DNS
    ├─ requête DNS AAAA → répond IPv6  ← Python essaie en 1er → TIMEOUT (~20s)
    └─ requête DNS A    → répond IPv4  ← bascule ici après échec
```

**Le système utilise `systemd-resolved`** (`nameserver 127.0.0.53` dans `/etc/resolv.conf`).

### Solutions

#### 1. Monkey-patch dans tagger.py (déjà en place) — suffisant pour ce projet

#### 2. `/etc/gai.conf` — fix système pour tous les programmes

Le fichier `/etc/gai.conf` contient déjà le commentaire explicatif. Il suffit de décommenter :
```
#precedence ::ffff:0:0/96  100
```

Commande :
```bash
sudo sed -i 's/#precedence ::ffff:0:0\/96  100/precedence ::ffff:0:0\/96  100/' /etc/gai.conf
```

Vérification :
```bash
python3 -c "import socket; print(socket.getaddrinfo('api.discogs.com', 443))"
# IPv4 doit apparaître en premier
```
